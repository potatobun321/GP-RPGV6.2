GP-RPGV6.2 - Development & Architecture Log

================================================================================
1. FEATURES IMPLEMENTED
================================================================================

[ ARCHITECTURE & ENGINE ]
- Modular Architecture: Successfully migrated the monolithic V6 codebase into the modular V6.2 structure (engine, content, scenes, tools).
- Global State Eradication: Removed fragile `_G` dependencies (e.g. _G.Editor, _G.game). All state is now cleanly managed by the `Context` and `Registry` (ECS) tables.
- Asset Memory Caching: Implemented `assets.lua`. The engine now caches textures (like `player.png` or `grass.png`) into RAM only once, rather than re-loading them for every entity, saving massive amounts of memory.

[ MAPS & RENDERING ]
- SpriteBatch Optimization: Replaced the dynamic tile-by-tile rendering loop (2,500+ draw calls) with a dynamic `SpriteBatch` mesh generator. The map now renders in 1-5 draw calls, massively boosting FPS.
- JSON Serialization: Swapped the dangerous `loadfile()` Lua-execution saving method for a secure, lightweight JSON parser (`json.lua`). Maps are now saved cleanly as readable JSON arrays.
- Dynamic Map Expansion: The engine now automatically recalculates map boundaries in real-time. If you paint a tile outside the current map limit, the engine flawlessly expands the boundaries to include it.
- Render Artifacts Removed: Removed the debug bounds overlay that was causing a floating bright line artifact when map bounds expanded asymmetrically.

[ CAMERA & CONSOLE ]
- Strict Boundary Zoom Clamping: Fixed a bug where zooming out would reveal areas outside of a user's defined `c-bounds`. The camera now physically locks its minimum scale relative to the boundary width/height.
- Free-Cam Override: The camera now completely ignores custom boundaries when Editor Mode or Free Camera mode (Shift+F) are active, allowing unrestricted panning across the whole map.
- Console UI Overhaul: Replaced messy ASCII borders in the `help` command with a clean, perfectly aligned layout.
- Console Scissor Masking: Added a 10px top-padding and hardware `setScissor` mask to the console so text gracefully slides out of view without rendering over the literal screen edge.


================================================================================
2. KNOWN BUGS & LINGERING ISSUES
================================================================================

- Legacy Clutter: Legacy `.lua` map files (e.g. `map.lua`) still exist in `content/maps` alongside their newly converted `.json` equivalents. The engine safely prioritizes JSON, but the directory is messy.
- Dead Code: 5 legacy scripts (`object.lua`, `character.lua`, `world.lua`, `dialogue.lua`, `game_state.lua`) remain in the V6.2 directory despite being entirely superseded by the ECS.
- Animated Tile Batching: The current `SpriteBatch` optimization works flawlessly for static tiles. If animated tiles (like moving water) are heavily utilized, they will require a specialized animated batching approach or shader.


================================================================================
3. NEXT FOCUS AREAS
================================================================================

1. Animated Map Tiles:
   Now that static tiles are batched into a single draw call, we need to implement a shader or secondary batch system for animated environmental tiles (water, lava) so they don't bottleneck the GPU.

2. Gameplay & Combat Logic:
   Now that the map and engine core are highly optimized, it is time to connect the `CharacterStats`, `Collider`, and `Health` ECS components. The focus should be on building a CombatSystem that handles hit-detection and damage floating text.

3. Scene Transitions & Loading:
   Currently, jumping between maps blocks the main thread. We should implement a dedicated "Transition" scene that handles smooth fade-ins and unloads memory gracefully without freezing the game window.

4. UI System Formalization:
   The Map Editor currently relies on custom UI math. We should formalize a standard `UI.lua` component library (buttons, sliders, panels) that can be easily used by both the map editor and the actual gameplay pause menus.
